# Личный AI-агент в Telegram на своём сервере (Codex) — инструкция под ключ (v3)

> v3 (19.08.2026): вся установка свёрнута в ОДИН скрипт — как в Claude-гайде.
> Руками остаются только сервер, два бота и вход в ChatGPT. Прежние пошаговые
> части оставлены ниже как «Ручной путь» — для понимания и на случай, когда
> скрипт недоступен.

**Для кого:** для человека без опыта в программировании.
**Что получишь:** личного AI-ассистента, который живёт в Telegram (пишешь ему в чат — он отвечает, ищет, пишет тексты, работает с файлами и выполняет задачи на сервере). Плюс второго агента-«ремонтника», который следит за первым, перезапускает его при сбоях и сообщает тебе. Оба крутятся на арендованном сервере 24/7 — свой компьютер держать включённым не нужно. Работает на твоей подписке ChatGPT (без платного API-ключа).
**Что понадобится:** подписка **ChatGPT Plus** (минимум) или **Pro**, банковская карта для аренды сервера (~300–500 ₽/мес), телефон с Telegram, ~2 часа времени.
**Сложность:** всё делается копированием готовых команд. Не нужно ничего понимать в коде — код напишет сам агент.

## Как пользоваться этой инструкцией

Идёшь строго сверху вниз, блок за блоком, ничего не пропуская. Встречаются три типа блоков:

- **В КОНСОЛЬ** — копируешь строку и вставляешь в окно Терминала, подключённого к серверу (подключимся на Шаге 1.3), жмёшь Enter.
- **В CODEX** — это задание самому агенту-программисту. Вставляешь текст в окно Codex.
- **В ChatGPT** — если что-то пошло не так и нужна помощь. Открываешь chatgpt.com, вставляешь блок ошибки — он объяснит и проведёт за руку.

**Золотое правило:** не понял шаг или вылезла ошибка — не гадай и не жми наугад. Скопируй весь текст ошибки, вставь в ChatGPT и спроси: «Делаю личного агента на Codex по инструкции, застрял на этом шаге, вот ошибка — что делать по шагам?»

**Про подключение к серверу:** ничего ставить не нужно — командуем сервером через обычный Терминал (Mac: Cmd+Пробел → «Терминал»; Windows: Terminal/PowerShell) по команде `ssh`. Веб-консоль хостинга не трогаем. После настройки Терминал больше не нужен — только пишешь боту в Telegram.

# БЫСТРЫЙ ПУТЬ: один скрипт вместо частей 2–8

Делаешь три подготовительных вещи, потом одну команду — всё остальное скрипт ставит сам.

**Шаг А — сервер.** Пройди Часть 1 ниже (аренда VDSina + вход через Терминал по ssh). Дальше все команды — в консоль сервера под root.

**Шаг Б — два бота.** Пройди Шаги 5.1–5.3 из Части 5: создай у @BotFather ДВУХ ботов (основной + ремонтник), узнай свой id у @userinfobot и нажми Start обоим ботам. На руках должно быть: два токена и твой id.

**Шаг Б½ — голосовые (по желанию).** Хочешь надиктовывать боту голосом — заведи бесплатный ключ распознавания: console.groq.com → регистрация → **API Keys → Create API Key** → скопируй ключ (начинается на `gsk_`). Скрипт спросит его на установке; Enter — пропустить, боту тогда можно только писать.

**Шаг Б¾ — ключ OpenAI для памяти (советую).** Агент ищет в своей памяти по смыслу («вернёмся к ДНС» найдёт запись про DNS). Без ключа это делает локальная модель, которая занимает **~2 ГБ оперативки** — на типичном сервере в 4 ГБ это половина. С ключом считает OpenAI, серверу ноль, стоит центы в месяц: platform.openai.com → **API keys → Create new secret key** (начинается на `sk-`). Скрипт спросит его на установке; Enter — пропустить (поставится локальная модель, если хватает памяти).

**Шаг В — одна команда.** В КОНСОЛЬ:
```
curl -fsSL https://raw.githubusercontent.com/popovalex17071985-source/JohnRamboAgent/main/scripts/install-codex.sh -o install-codex.sh && bash install-codex.sh
```
Скрипт спросит два токена, твой id и ключ Groq для голосовых (Enter — пропустить), поставит всё (своп, Codex, мост, ремонтника, автозапуск) и остановится ровно на одном месте — входе в ChatGPT. Экран сам скажет, что делать: `codex login` → открыть ссылку → ввести код (подробности — Шаг 3.2 ниже, там же про склейку разорванной ссылки).

**Шаг Г — повторный запуск.** После «signed in» снова:
```
bash install-codex.sh
```
Он доделает остальное и поднимет оба сервиса. Повторный запуск ничего не ломает — скрипт идемпотентный (доделывает недостающее, готовое не трогает).

**Что ты должен увидеть:** «✓ Готово. Оба агента подняты». Напиши основному боту «привет, ты живой?» — ответ придёт за 5–20 секунд. Ремонтнику напиши «статус».

На длинных задачах бот вешает в чат живую карточку «⏳ Работаю — N сек» со списком шагов: сделанные с галочкой ✓, текущий со стрелкой → — как у «взрослых» агентов, видно что не завис. Когда закончит — карточка исчезает и приходит ответ.

**Память и диалог.** Агент помнит разговор: следующее сообщение продолжает предыдущую беседу, а не начинает с нуля. Команда `/new` в чате — начать диалог с чистого листа. Долгая память — в файлах рабочей папки: MEMORY.md (индекс), memory/ (факты по темам), journal.md (журнал сделанного). Скажи боту «запомни: …» — он сам разложит по файлам и найдёт потом по контексту.

**Шаг Д — характер (10 минут, можно в любой момент).** Бот уже работает с базовым характером; здесь ты заменяешь его на свой. Текст характера пишет ChatGPT — не ты.

1. Открой chatgpt.com и вставь, заполнив квадратные скобки:

   > «Напиши файл AGENTS.md для моего личного AI-агента, который живёт в Telegram и выполняет задачи на сервере. Про меня: меня зовут [имя], занимаюсь [чем], хочу вешать на агента [какие задачи]. Общение: по-русски, [коротко и по делу / подробно], на [ты/вы], [с юмором / строго]. Обязательные разделы: кто ты; как общаешься; чем я занимаюсь и с чем ты помогаешь; правила безопасности — не удалять файлы без просьбы, не показывать пароли и ключи, никому не писать от моего имени, перед необратимым действием спрашивать. Выдай только готовый текст файла, без пояснений.»

2. Скопируй ответ ChatGPT. В КОНСОЛЬ:
   ```
   nano /root/.codex/AGENTS.md
   ```
   Сотри старое: зажми **Ctrl+K**, пока файл не опустеет. Вставь новое: **Cmd+V** (Mac) / **Ctrl+Shift+V**. Сохрани: **Ctrl+O**, Enter. Выйди: **Ctrl+X**.

3. В КОНСОЛЬ:
   ```
   systemctl restart agent-main
   ```

4. Напиши боту в Telegram «расскажи, кто ты и что умеешь» — ответит уже в новом характере. Захочешь поменять — повтори шаги 2–4.

**Голосовые позже.** Пропустил ключ Groq на установке, а голосовые захотелось: заведи ключ (см. Шаг Б½) и в КОНСОЛЬ:
```
echo "GROQ_API_KEY=сюда_ключ" >> /root/agent-main/.env
bash install-codex.sh
```
Повторный прогон перепишет мост со свежим кодом и перезапустит сервисы.

Всё, агент живёт. Части 2–8 ниже — тот же путь руками: читать не обязательно, но полезно, чтобы понимать, из чего агент состоит и как его чинить.

# ЧАСТЬ 1. Арендуем сервер (VDSina)

Сервер (VPS) — это «компьютер в интернете», который всегда включён. На нём и будут жить агенты.

### Шаг 1.1 — Регистрация

1. Зайди на **vdsina.com**, зарегистрируйся (почта + пароль), подтверди почту.
2. Пополни баланс картой — хватит ~300–500 ₽ на первый месяц.

### Шаг 1.2 — Создать сервер

Нажми **«Создать сервер»** и выбери:
- **Тип:** обычный VPS (виртуальный сервер).
- **ОС:** **Ubuntu 24.04** (если нет — 22.04). Вся инструкция под неё.
- **Тариф:** минимальный с **2 ГБ RAM** и **1 CPU**. Одного гигабайта мало — бери 2 ГБ.
- **Локация:** **Нидерланды (Амстердам)** — чистый европейский IP.

Создай. Через 1–2 минуты в панели у сервера появятся:
- **IP-адрес** (вида 91.xxx.xxx.xxx),
- **пароль root** (главный пароль сервера; иногда приходит на почту или показывается один раз — сохрани. Не видно — нажми «сбросить/переустановить пароль»).

Запиши IP и пароль — они понадобятся дальше.

### Шаг 1.3 — Зайти на сервер через Терминал

Открой Терминал (Mac: Cmd+Пробел → набери «Терминал», Enter. Windows: Terminal/PowerShell).

В ТЕРМИНАЛ (подставь IP сервера из Шага 1.2):
```
ssh root@ТВОЙ_IP
```
Первый раз спросит «yes/no» — набери `yes`, Enter. Потом попросит пароль root из Шага 1.2 — вставь (символы при вводе НЕ видно, это нормально), Enter.

**Что ты должен увидеть:** приглашение вида `root@v123456:~#` — ты внутри сервера. Всё, что дальше помечено **В КОНСОЛЬ**, вставляешь в это окно (Cmd+V на Mac, Ctrl+Shift+V в Windows-терминале).

> Если пишет ошибку — проверь IP и пароль (пароль можно сбросить в панели VDSina). Не помогло — скопируй сообщение об ошибке в ChatGPT.
> Окно закрыл или связь оборвалась — просто снова `ssh root@ТВОЙ_IP`.

# ЧАСТЬ 2. Готовим сервер

### Шаг 2.1 — Обновить систему

В КОНСОЛЬ:
```
apt update && apt upgrade -y
```
Идёт минуту-две. Если что-то спросит — жми Enter.

### Шаг 2.1.1 — Подстраховка памяти (своп)

Если взял сервер с 2 ГБ — шаг всё равно не повредит, а на 1 ГБ он обязателен:
без него сервер может намертво зависнуть посреди установки (проверено).

В КОНСОЛЬ (одним блоком):
```
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```
**Что ты должен увидеть:** строку «Setting up swapspace…». Проверка: `free -h` —
в строке Swap должно быть 2.0Gi.

### Шаг 2.2 — Поставить базовые утилиты

В КОНСОЛЬ:
```
apt install -y curl git nano
```

# ЧАСТЬ 3. Ставим Codex и входим по подписке ChatGPT

### Шаг 3.1 — Установка Codex

В КОНСОЛЬ:
```
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```
Затем, чтобы система «увидела» новую команду:
```
source ~/.bashrc
```
Проверка — В КОНСОЛЬ:
```
codex --version
```
Показал номер версии — отлично. Если «command not found» — выйди с сервера (`exit`) и зайди снова (`ssh root@ТВОЙ_IP`), потом повтори проверку.

### Шаг 3.2 — Вход через подписку (без API-ключа)

На сервере нет браузера, поэтому входим по короткому коду устройства.

**Сначала включи вход по коду** — у OpenAI он по умолчанию выключен, и без него код не примется: на chatgpt.com → аватарка → **Настройки → Безопасность** → включи **«Авторизация с помощью кода устройства»**.

В КОНСОЛЬ:
```
codex login --device-auth
```
Codex покажет **короткий код и адрес**. Открой адрес в браузере на любом устройстве (можно на телефоне), войди в аккаунт **ChatGPT** (тот, где оплачена подписка) и введи код.

> Если сайт пишет «Включите авторизацию с помощью кода устройства» — это тумблер, который у OpenAI по умолчанию выключен: на chatgpt.com → аватарка → **Настройки → Безопасность** → включи **«Авторизация с помощью кода устройства»**, затем снова запусти `codex login --device-auth`.

> ⚠️ Терминал может разорвать длинную ссылку на несколько строк. Копируй все
> куски и склеивай в ОДНУ строку без переносов и пробелов — иначе браузер её
> не откроет. Возьми телефон, открой эту ссылку в браузере, залогинься своим аккаунтом **ChatGPT** (тем, где оплачена Plus/Pro), введи показанный код и подтверди. Вернись в консоль — появится «signed in».

> Запасной путь, если `--device-auth` не сработал: на своём компьютере открой новое окно Терминала → `ssh -L 1455:localhost:1455 root@ТВОЙ_IP` → в нём `codex login` → показанную ссылку склей в ОДНУ строку без пробелов и открой в браузере ТОГО ЖЕ компьютера. «Oops / Route Error» в браузере = открыл ссылку без этого туннеля или на другом устройстве.

**Про лимиты подписки:**
- Plus — рабочий минимум. Pro даёт лимит в разы больше.
- Лимит считается «скользящим окном» за 5 часов. На общение и обычные задачи хватает; если гонять тяжёлое пачками — можешь упереться, тогда подожди пару часов.
- Проверить остаток: команда `/status` внутри Codex, либо страница chatgpt.com/codex/settings/usage.

# ЧАСТЬ 4. Задаём характер агента под свои задачи

Это самое важное и самое личное. Здесь ты описываешь, КЕМ будет твой агент, КАК он общается и ЧТО делает. От этого зависит, будет он полезным помощником или безликой болталкой.

### Шаг 4.1 — Технические настройки (общие для всех)

В КОНСОЛЬ:
```
mkdir -p ~/.codex && nano ~/.codex/config.toml
```
Откроется редактор nano. Вставь:
```
# Модель не задаём: Codex сам берёт ту, что доступна на твоей подписке
# (прибитая gpt-5.5 давала 404 «model does not exist» на части аккаунтов, 25.09.2026)

# "never" = агент не переспрашивает на каждом шаге (нужно для автономной работы)
approval_policy = "never"

# Песочница: агент пишет только в рабочей папке — безопасный режим
sandbox_mode = "workspace-write"
```
Сохрани: **Ctrl+O**, Enter. Выйди: **Ctrl+X**.

> Режим `danger-full-access` (полный доступ ко всему серверу) не включай, пока не будешь понимать, зачем он нужен.

### Шаг 4.2 — Продумай характер (5 минут с ручкой)

Прежде чем писать файл, ответь себе на вопросы — это и станет «душой» агента:

1. **Имя.** Как зовут ассистента? (напр. Макс, Ева, Джарвис)
2. **Роль.** Кто он тебе? (личный ассистент / помощник по работе / редактор / аналитик…)
3. **Твои задачи.** Чем ты занимаешься и с чем он должен помогать? Перечисли конкретно: «веду интернет-магазин», «пишу тексты и посты», «свожу таблицы с цифрами», «отвечаю клиентам» и т.п.
4. **Стиль общения.** Коротко и по делу или подробно с пояснениями? На «ты» или на «вы»? С юмором или строго? По-русски?
5. **Красные линии.** Чего он НЕ должен делать без твоего разрешения? (удалять файлы, тратить деньги, писать кому-то от твоего имени…)

### Шаг 4.3 — Запиши характер в файл AGENTS.md

Codex читает файл `AGENTS.md` как постоянную инструкцию — это его «характер и правила», действуют в каждом ответе.

В КОНСОЛЬ:
```
nano ~/.codex/AGENTS.md
```
Вставь этот шаблон и **замени всё в квадратных скобках** на свои ответы из Шага 4.2:
```
# Кто ты

Ты — [РОЛЬ, напр. мой личный ассистент по работе]. Зовут тебя [ИМЯ].
Общаешься со мной в Telegram. Я читаю Telegram, а не терминал —
поэтому всё, что хочешь сказать, отправляй ответом в чат.

# Как ты общаешься
- Язык: русский.
- [Коротко и по делу, без воды и извинений] / [подробно, с пояснениями].
- Обращение на [ты] / [вы].
- Тон: [спокойный и деловой] / [дружеский, можно с юмором].
- Сначала — суть или результат, потом пояснения.
- Задача непонятна — задай уточняющий вопрос, не выдумывай.

# Чем я занимаюсь и с чем ты помогаешь
- [Например: веду оптовые продажи техники — помогаешь считать, писать тексты, вести таблицы].
- [Задача 2].
- [Задача 3].

# Что ты умеешь
- Отвечать на вопросы, искать и структурировать информацию, писать тексты.
- Работать с файлами в рабочей папке.
- Выполнять команды на сервере (в пределах безопасной песочницы).

# Правила безопасности (красные линии)
- Никогда не удаляй файлы и данные без моей явной просьбы.
- Никогда не показывай пароли, токены и ключи.
- Не пиши никому от моего имени без разрешения.
- [Свои ограничения].
- Сомневаешься в опасном/необратимом действии — сначала спроси меня.
```
Сохрани: **Ctrl+O**, Enter, **Ctrl+X**.

### Шаг 4.4 (рекомендую) — Отполировать характер через ChatGPT

Хочешь характер поживее и поточнее — попроси ChatGPT собрать его за тебя. Открой chatgpt.com и вставь:

> «Помоги написать файл AGENTS.md для моего личного AI-агента на Codex, который живёт в Telegram. Опиши его характер, стиль общения по-русски, что он умеет и правила безопасности. Обо мне: [имя, чем занимаюсь, какие задачи хочу на него повесить, какой тон мне нравится]. Дай готовый текст, который я просто скопирую в файл.»

Полученный текст вставь в `AGENTS.md` (Шаг 4.3) вместо шаблона.

# ЧАСТЬ 5. Заводим двух Telegram-ботов

Нужно два бота: **основной** (сам ассистент) и **ремонтник** (второй агент, который следит за основным и чинит его). Заведём оба сразу.

### Шаг 5.1 — Создать ботов через BotFather

В Telegram открой **@BotFather** (с синей галочкой), нажми **Start**. Затем дважды создай бота:

**Бот 1 — основной:**
1. Отправь **/newbot**.

```
Используй только curl и стандартные утилиты Linux, без установки лишнего.
Сделай файл исполняемым (chmod +x bridge.sh).
После создания — коротко объясни, как запустить.
```

# ЧАСТЬ 7. Автозапуск основного агента 24/7 (systemd)

На сервере автозапуском заведует systemd: держит агента включённым и поднимает при падении.

### Шаг 7.1 — Файл сервиса

В КОНСОЛЬ:
```
nano /etc/systemd/system/agent-main.service
```
Вставь как есть:
```
[Unit]
Description=Main Codex Telegram agent
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/agent-main
ExecStart=/root/agent-main/bridge.sh
Restart=always
RestartSec=5
Environment=PATH=/root/.local/bin:/usr/local/bin:/usr/bin:/bin

[Install]
WantedBy=multi-user.target
```
Сохрани (**Ctrl+O**, Enter, **Ctrl+X**).

> Строка `Environment=PATH=…` должна содержать папку, куда установился codex. Узнать её: команда `which codex`. Если путь отличается — подставь его директорию в начало PATH.

### Шаг 7.2 — Включить

В КОНСОЛЬ:
```
systemctl daemon-reload
systemctl enable --now agent-main
systemctl status agent-main
```
**Что ты должен увидеть:** зелёное «active (running)». Напиши боту в
Telegram — должен ответить, как в ручной проверке.

Полезное на будущее:
- Логи: `journalctl -u agent-main -n 50`
- Перезапуск: `systemctl restart agent-main`
- Остановить: `systemctl stop agent-main`

# ЧАСТЬ 8. Второй агент — ремонтник (следит и чинит)

### Шаг 8.2 — Просим Codex написать ремонтника

```
cd ~/agent-watchdog && codex
```
**В CODEX:**
```
Напиши bash-скрипт watchdog.sh в папке ~/agent-watchdog — это агент-ремонтник
основного Telegram-агента (сервис systemd называется agent-main).

Часть 1 — автопроверка каждые 60 секунд (фоновый цикл):
1. Читай TELEGRAM_TOKEN и TELEGRAM_CHAT_ID из .env в этой папке.
2. Проверяй, активен ли основной сервис: systemctl is-active agent-main.
3. Проверяй его лог ~/agent-main/err.log: если за последние 5 минут

5. Если всё хорошо — молчи.

Часть 2 — общение со мной через его собственный бот (long polling):
6. Параллельно слушай сообщения этого бота (getUpdates) от TELEGRAM_CHAT_ID.
7. На моё сообщение отвечай про состояние основного агента, а для сложных
   вопросов запускай codex -a never exec --sandbox workspace-write "мой текст".
8. Понимай команды по-русски: "перезапусти основного" -> systemctl restart agent-main;
   "статус" -> покажи systemctl is-active agent-main и последние строки err.log.

Ошибки логируй в err.log этой папки, цикл не останавливай.

```

```
ExecStart=/root/agent-watchdog/watchdog.sh
```

# ЧАСТЬ 9. Память (чтобы агент помнил, как ты)

По умолчанию каждый ответ — «с чистого листа»: агент забывает всё, как только ответил. Сделаем ему настоящую долгую память — трёхслойную, по той же схеме, что у продвинутых ассистентов.

**Три слоя памяти:**
1. **Характер и правила** — файл `AGENTS.md` из Части 4. Грузится в каждый ответ, это стержень. Уже готов.
2. **Долгая память фактов** — папка `memory/` с файлами «один факт = один файл» и оглавлением `MEMORY.md`. Оглавление подкладывается перед каждым запросом, а сам факт агент открывает, когда он нужен. Факты по категориям: **про тебя** (кто ты, что любишь), **про задачи/проекты** (что ведём, договорённости), **уроки** (на чём ошибся — чтобы не повторять).
3. **Заметки-решения** — короткий лог «что решили и почему», чтобы через месяц не гадать.

### Шаг 9.1 — Просим Codex собрать память

В CODEX (в папке ~/agent-main):
```
Сделай мне трёхслойную долгую память для агента. Структура:
- Папка memory/ рядом с bridge.sh.
- Файл memory/MEMORY.md — это ОГЛАВЛЕНИЕ: одна строка на факт,
  вида "- [короткий заголовок](имя-файла.md) — суть в 5-7 слов".
- Отдельные файлы memory/<slug>.md — по одному факту в каждом,
  с пометкой категории вверху: user | project | lesson.

Доработай bridge.sh так, чтобы:
1. Перед КАЖДЫМ запросом подкладывать в контекст содержимое AGENTS.md
   и оглавление memory/MEMORY.md (не все файлы целиком — только оглавление).
2. Если оглавление показывает релевантный факт — сначала прочитай нужный
   файл memory/<slug>.md, потом отвечай.
3. Если я пишу "запомни: ..." — заведи новый файл-факт, проставь категорию
   и допиши строку в оглавление MEMORY.md.
4. Ты и сам, без команды, сохраняй важное (мои предпочтения, договорённости,
   свои ошибки) — тем же способом. Одна мысль — один файл, коротко.
5. Если новый факт противоречит старому — обнови старый файл, не плоди дубли.

Не раздувай файлы. Заведи для примера memory/about-me.md (категория user)
с парой фактов обо мне и добавь его в оглавление.
```
После правки перезапусти: `systemctl restart agent-main`.

### Шаг 9.2 — Как пользоваться

- Хочешь что-то закрепить — пиши боту **«запомни: …»** (напр. «запомни: я на ты, пиши коротко»).
- Спроси **«что ты обо мне помнишь?»** — агент зачитает оглавление.
- Хочешь стереть факт — **«забудь про …»**, он удалит файл и строку из оглавления.

> Это рабочая, но простая память. Дальше её можно прокачивать (поиск по фактам, устаревание старых записей) — но для повседневного «помнит меня и наши дела» этого достаточно.

# Повседневное управление (когда всё уже работает)

Команд в чате у самодельного моста нет — управляешь фразами и консолью.

**Фразы боту-ремонтнику** (он понимает по-русски):
- «статус» — жив ли основной, последние ошибки;
- «перезапусти основного» — рестарт без захода на сервер.

**Консоль (ssh), если ремонтник сам лёг:**
```
systemctl status agent-main          # жив ли основной
systemctl restart agent-main         # перезапустить основного
systemctl restart agent-watchdog     # перезапустить ремонтника
journalctl -u agent-main -n 50       # логи основного
```

# Почему агент вдруг «тупеет» и что делать

У этой схемы два узких места, и оба видно заранее.

**1. Лимит подписки ChatGPT.** Считается скользящим окном за 5 часов. Симптом:
агент отвечал нормально, а потом стал отвечать ошибкой или молчать, хотя сервис
«active (running)». Проверка: остаток на chatgpt.com/codex/settings/usage.
Лечение: подождать пару часов, много работы каждый день — переходить на Pro.

**2. Разросшаяся память.** Каждый запрос мост подкладывает агенту `AGENTS.md` и
оглавление `MEMORY.md`. Пока оглавление на пару экранов — всё летает. Когда фактов
станут сотни, агент начнёт медленнее отвечать и хуже попадать в нужный факт.
Симптом: «раньше помнил, теперь путает». Лечение: попросить агента «почисти
память — объедини дубли и убери устаревшее».

В отличие от Claude-версии, здесь нет «распухшего разговора»: мост запускает
Codex на каждое сообщение заново, длинного диалога он не накапливает. Поэтому
команда «сжать контекст» тут не нужна — непрерывность даёт память из Части 9.

# Шпаргалка: частые проблемы

- **«command not found: codex»** — выйди (`exit`) и зайди снова по ssh. Не помогло — повтори Часть 3.1.
- **Бот не отвечает** — смотри логи: `journalctl -u agent-main -n 50` и `cat ~/agent-main/err.log`. Ошибку — в ChatGPT.
- **Отвечает всем подряд** — в `.env` неверный `TELEGRAM_CHAT_ID` (перепроверь через @userinfobot).
- **Уперся лимит подписки** — подожди пару часов (окно 5 ч) или перейди на Pro. Остаток: `/status` в Codex.
- **Поменять характер** — отредактируй `~/.codex/AGENTS.md`, затем `systemctl restart agent-main`.
- **Сервис не стартует** — `systemctl status <имя>` и `journalctl -u <имя> -n 50` покажут причину; скопируй в ChatGPT.
