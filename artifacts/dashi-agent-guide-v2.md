# Свой AI-агент как Jarvis — с нуля за 15 минут (v13)

**Сервер + Claude Code на подписке + плагин dashi + Telegram. Работает 24/7,
понимает голос, помнит контекст, сам переподнимается, ноль кнопок
подтверждения.**

Инструкция для человека без опыта. Делай ровно по шагам сверху вниз — каждый
шаг говорит, что вставить и что ты должен увидеть. Ничего не пропускай: шаги
идут в том порядке, в котором нужны.

> v13 (06.09.2026, после полного прогона установки с нуля в чистой системе и
> живой установки человеку), что нового: установщик научился забирать годовой
> токен с экрана, даже когда тот напечатан цветным (цветовые коды рвали его
> пополам, и установка сваливалась в ручной ввод), а сам ручной ввод больше не
> залипает намертво, если первым куском вставили код со страницы вместо токена.

# Пошаговая установка

## Шаг 0. Собери всё нужное (10 минут)

Без этого дальше идти нельзя.

1. **VPS.** Берём на **VDSina** (vdsina.com) — на нём живут наши агенты,
   проверено. Любой другой хостинг тоже подойдёт, требования те же.
   - **Ubuntu 22.04 или новее** — при заказе выбирается в списке образов.
   - **Минимум:** 2 ядра, 2 ГБ памяти, 20 ГБ диска. Хватит одному агенту без
     браузера и тяжёлых задач.
   - **Рекомендую:** 4 ядра, 4 ГБ памяти, 40 ГБ диска. Столько нужно, если
     ставится браузер (а он ставится по умолчанию) и агент будет что-то
     разбирать и считать.
   - **С запасом:** 4 ядра, 8 ГБ, 80 ГБ. Ровно на такой конфигурации крутится
     Jarvis со всеми задачами, бэкапами и вторым ботом.
   - Цены смотри на vdsina.com — они меняются, не хочу врать цифрами.

   После оплаты на почту придут: **IP-адрес**, логин `root` и **пароль**.
2. **Телеграм-бот.** В Telegram найди **@BotFather** → напиши `/newbot` → он
   спросит имя (любое) и username (обязан заканчиваться на `bot`) → пришлёт
   **токен** вида `7712345678:AAH...`. Скопируй его.
3. **Второй бот — ремонтник.** Там же у @BotFather сделай ещё одного:
   `/newbot` → имя типа `MyAgentRepair` → username, тоже на `bot` → второй
   **токен**. Это страховка: если основной агент замолчит, пишешь ремонтнику,
   и он его поднимает без терминала. Установщик спросит оба токена в одном
   прогоне, так что лучше принести сразу. Подробности — шаг 8.
4. **Свой id.** Найди **@userinfobot** → нажми Start → он пришлёт число вроде
   `140141496`. Это твой id.
5. **Найди обоих ботов по username и нажми Start у каждого.** Без этого
   бот не имеет права написать тебе первым.
6. **Подписка Claude** — Pro или Max, оформлена на claude.ai. Для круглосуточной
   работы бери Max.
7. *(по желанию)* **Ключ Groq** для голосовых: console.groq.com → Create API Key →
   строка на `gsk_`. Бесплатно, можно добавить потом.

> ⚠️ Токен бота — это пароль от бота. Засветил в чате или на скриншоте — сразу
> @BotFather → `/revoke`, получишь новый.

## Шаг 1. Зайди на сервер

На Mac/Linux открой Терминал, на Windows — приложение «Терминал» или PowerShell,
и вставь (подставь свой IP):

```
ssh root@123.45.67.89
```

Спросит «are you sure» — напиши `yes`. Спросит пароль — вставь его. **Пароль при
вводе не отображается, это нормально**, просто вставь и нажми Enter.

**Что ты должен увидеть:** приглашение вида `root@vps:~#`. Значит, ты внутри
сервера, и всё дальнейшее выполняется там.

## Шаг 2. Запусти установщик

Вставь обе строки целиком:

```
curl -fsSL https://raw.githubusercontent.com/popovalex17071985-source/JohnRamboAgent/main/scripts/install-agent.sh -o install-agent.sh
sudo bash install-agent.sh
```

Он спросит по очереди — ровно это и в этом порядке:

- **имя агента** — латиницей, без пробелов, например `jarvis`;
- **часовой пояс** — установщик покажет список городов и спросит твой. Пиши
  просто город: «Пермь», «Москва», «Новосибирск» — он сам подставит нужный код
  (можно и код целиком, вида `Asia/Yekaterinburg`). Enter — оставит пояс сервера.
  По этому поясу агент считает ВСЁ время: утренняя сводка в 09:00, ночные
  задачи, любое «во сколько»;
- **токен бота** — из шага 0;
- **твой id** — число из шага 0;
- **ключ Groq** — вставь или Enter, если пропускаешь (голосовые можно включить потом);
- **ключ OpenAI** — советую вставить: с ним агент заметно точнее вспоминает
  прошлое и не тратит ~0,7 ГБ оперативки сервера, стоит центы в месяц. Нет ключа —
  Enter, память всё равно встанет (локально, похуже);
- **«Поехали? [Y/n]»** — покажет имя, папку и сервис, жми Enter.

Дальше он сам поставит систему, Node.js, Claude Code, заведёт отдельного
пользователя, Bun, рабочую папку, плагин, конфиг, хуки и автозапуск. Это
5–10 минут, в это время ничего делать не надо.

Дальше он остановится ещё четыре раза, ровно в таком порядке:

- **«Включить шифрованный бэкап? [Y/n]»** — Enter. Появится **пароль от бэкапа**
  — жёлтая строка на экране. Сохрани её в менеджер паролей ПРЯМО СЕЙЧАС: этим
  паролем шифруются копии, без него облачная копия — мусор. Сохранил — Enter;
- **строка токена Google Drive** — сразу следом установщик предложит подключить
  облачную копию бэкапа. Как получить строку — в шаге 9; можно пропустить
  через Enter и вернуться позже;
- **вход в Claude** — это шаг 3, самое ответственное место;
- **токен бота-ремонтника** — уже в самом конце. Это второй бот-страховка,
  подробности в шаге 8. Нет под рукой — Enter, поставишь позже.

Заодно он поставит агенту браузер (Playwright + Chromium) — без него агент не
сможет ходить в веб-кабинеты, где нет API. Не нужен — запусти с `--no-browser`.

**Про часовой пояс подробнее.** Сервер обычно живёт в Москве или в UTC, а ты —
нет: без правильного пояса утренняя сводка придёт не в 09:00, а когда придётся.
Поэтому установщик спрашивает пояс сам и сразу показывает, который час в
выбранном месте — сверь с настенными часами, это и есть проверка. Ошибся или
нажал Enter не глядя — не страшно: запусти установщик ещё раз с явным поясом,
крон переставится:

```
sudo bash install-agent.sh --tz Asia/Yekaterinburg
```

Флагу `--tz` тоже можно скормить город: `--tz Пермь`.

**Все флаги установщика** (нужны не всем; всё то же он умеет спросить сам):

| Флаг | Что делает |
|---|---|
| `--name jarvis` | имя агента (иначе спросит) |
| `--token 123:AA...` / `--user-id 140141496` | токен бота и твой id (иначе спросит) |
| `--tz Asia/Yekaterinburg` (или `--tz Пермь`) | твой часовой пояс: утренняя сводка и будильник в 09:00 по нему. Без флага установщик спросит сам |
| `--claude-token sk-ant-oat01-...` | готовый годовой токен Claude — тогда вход на сервере не нужен (шаг 3) |
| `--model opus` | модель агента (`opus`, `sonnet`, `haiku` или полный id); без флага — дефолт аккаунта |
| `--groq-key gsk_...` | голосовые сообщения |
| `--openai-key sk-...` | семантическая память OpenViking (docker), см. раздел «Семантическая память» |
| `--repair-token 123:BB...` | бот-ремонтник (шаг 8) |
| `--no-browser` | не ставить Playwright/Chromium (экономит ~400 МБ) |
| `--branch feature/x` | staging-агент: обновляется с этой ветки, а не с `main`. Один раз указал — дальше помнит |
| `--user NAME` + `--webhook-port PORT` | **второй агент на том же сервере**: ему нужны свой системный пользователь и свой порт (не 8089). Оба флага сразу, иначе установщик остановится и объяснит |
| `--yes` | без вопросов (для автоматики); необязательное пропускается |

**Что ты должен увидеть:** зелёные галочки `✓` и в какой-то момент — вход в
Claude. Это шаг 3.

## Шаг 3. Войди в Claude (единственное ручное место)

Установщик сам запустит вход (`claude setup-token`) и проведёт по шагам —
никуда выходить и ничего перезапускать не надо:

1. На экране появится ссылка. Терминал может разорвать её на несколько строк —
   скопируй все куски и склей в ОДНУ строку без переносов и пробелов, иначе
   браузер её не откроет. Открывать — **на своём компьютере**, не на сервере.
2. Войди аккаунтом, на котором оформлена подписка (Pro/Max).
3. Браузер покажет код — скопируй его и вставь обратно в терминал, Enter.

Токен получается сразу **на год** — перелогиниваться раз в месяц не придётся.
Установщик заберёт его с экрана сам; не смог — попросит вставить.

> ⚠️ Вставляй **только сам токен** — строку, которая начинается на
> `sk-ant-oat01-`. Код со страницы браузера (тот, что вставлял на шаге 3) сюда
> не годится: установщик будет ждать токен и повторять вопрос. Если токен
> напечатан в две строки — вставь сначала первую, Enter, потом вторую, Enter.

**Что ты должен увидеть:** `✓ годовой токен записан` — и установка продолжится
сама до сообщения, что сервис запущен.

> ⛔ **Не жми Ctrl-C на этом экране.** Пока висит `Paste code here if prompted >`,
> установщик ЖДЁТ код из браузера — это не зависание. Выйдешь на этом месте —
> токена не будет, агент поднимется, но в ответ на сообщения промолчит.
> Сходил за кодом, вернулся, вставил, Enter — всё.

> ⚠️ Из России сам сайт claude.ai может не открываться даже с VPN, а вход по
> этой ссылке — работает: это отдельная страница входа. Перенести вход с Mac
> (`scp ~/.claude`) или из десктопного приложения НЕ выйдет — там другие токены.

> 💡 Можно вообще без ручного шага на сервере: сделай `claude setup-token` на
> любой своей машине с Claude Code и передай результат установщику флагом
> `--claude-token sk-ant-oat01-...` — тогда он пройдёт от начала до конца сам.

> 💡 Модель агента: по умолчанию — та, что стоит дефолтом у аккаунта владельца.
> Хочешь задать явно — добавь флаг `--model opus` (или `sonnet`, `haiku`, полный
> id модели). Поменять потом: строка `DASHI_MODEL=` в
> `/etc/dashi-plugin/<имя>/channel.env` и `systemctl restart dashi-<имя>`.

**Первый разговор.** Свежий агент при первом же сообщении сам представится и
задаст 3–4 вопроса: как обращаться, чем занимаетесь, какие задачи будете
поручать, часовой пояс. Ответьте нормально один раз — он запишет это себе в
память и в CLAUDE.md и больше переспрашивать не будет. С этого и начинается
его картина мира.

## Шаг 4. Повторный запуск — доделать прерванное и обновить агента

Первая установка идёт одной командой до конца. Повторный прогон нужен в двух
случаях: связь оборвалась / ты прервал скрипт — или ты хочешь **обновить
агента**. Команда та же, только имя лучше передать флагом, чтобы не опечататься:

```
sudo bash install-agent.sh --name <имя> --tz Asia/Yekaterinburg
```

Имя агента — **то же самое**, буква в букву, иначе начнёт заводить второго
агента с нуля. Токен бота и id не спросит — они уже записаны; спросит только
то, чего ещё нет (например, токен ремонтника, если пропускал). Всё сделанное
пропустит и доделает остальное.

Что делает повторный прогон, кроме доделки:

- **обновляет плагин** до свежей версии той ветки, на которой агент сидит:
  ветку он помнит из конфига (`DASHI_BRANCH` в `channel.env`), так что
  `--branch` второй раз передавать не надо. Если в папке плагина есть
  локальные правки — обновление пропустит с предупреждением, а не сотрёт их;
- **обновляет комплект дисциплины** (конституцию, гейт-хуки, помощников,
  скрипты сводки). Если какой-то из этих файлов ты правил руками — старую
  версию он сначала положит в `~/.claude-lab/<имя>/.kit-backup/<дата-время>/`
  и напишет «сохранил N старых файлов в …». Личное (CLAUDE.md, память,
  `core/rules.md`, леджер) не трогает вовсе;
- `--tz` с новым поясом переставит утренние кроны (сводку, будильник, советника,
  самопроверку, отчёт о сервере) на новый час; пояс запоминается в `channel.env`,
  так что `/update` и следующий прогон без флага его не собьют;
- возвращает юзеру владение всей его домашней папкой (root-починки больше не
  оставляют мин);
- **перезапускает агента** в самом конце — он предупредит: «связь моргнёт,
  текущий ход агента оборвётся». Без перезапуска новые хуки и плагин не
  подхватятся. Поэтому не запускай повторный прогон посреди важной работы
  агента.

> Это и есть **штатный способ обновить агента целиком**. Команда `/update` из
> чата делает большую часть того же без root: обновляет код моста (git + bun)
> и заново раскладывает комплект дисциплины (правила, стопоры, помощников,
> утренние кроны — по твоему поясу). Не трогает она только то, что живёт под
> root: юнит systemd, `dashi-ctl`, хуки плагина, канарейку. Для этого —
> повторный прогон установщика.

## Что агент умеет с первого дня (ставить ничего не надо)

Раньше установщик давал «скелет»: агент живой и разговаривает, а способ работы
ты нарабатывал сам месяцами. С 27.08.2026 он ставится сразу с тем укладом,
который Jarvis выстрадал на реальных ошибках. Отдельно включать нечего.

**Правила, которые всегда у него перед глазами.** Зоны самостоятельности
(обратимое делает сам, необратимое спрашивает), запрет делать выводы по
косвенным признакам вместо первоисточника, обязанность самому доложить о
результате и предложить следующий шаг, запрет отвечать «не могу» раньше пяти
испробованных путей.

**Автоматические стопоры.** Они не зависят от настроения агента и срабатывают
сами: блок опасных команд, блок необратимых действий без твоего слова, обрезка
гигантского вывода, отказ принять «урок» без реальной правки в правилах или
скрипте, страж языка системных файлов, ловец обещаний «вернусь позже».

**Леджер — единая доска открытых дел.** Всё обещанное попадает туда само.
Каждое утро в **09:00 по твоему времени** (не по времени сервера) агент
присылает сводку: что на тебе, что на нём, что просрочено. Раскрывающимся
списком, обычными словами.

**Ремонтник — второй бот-страховка.** Ставится в том же прогоне. Если основной агент замолчал (упал вход, завис сервис), пишешь ремонтнику — он смотрит логи и поднимает основного. Подробнее — шаг 8.

**Три помощника** для проверки выводов, разбора кода и черновой работы —

## Шаг 9. Облачная копия бэкапа (10 минут, но это спасение сервера)

Установщик уже завёл шифрованный бэкап: каждую ночь в 03:40, в папку внутри
сервера. Проблема очевидная — умрёт сервер, умрёт и копия. Нужно, чтобы архив
уезжал на Google Drive.

Если ты подключил диск прямо во время установки — этот шаг уже сделан, пропускай.

Вход в гугл требует браузера, а на сервере его нет. Поэтому вход проходишь у себя
на компьютере, а на сервер переносишь только результат.

1. На СВОЁМ компьютере, в отдельном окне терминала — НЕ внутри ssh на сервер,
   поставь rclone. На маке одной строкой (спросит пароль от мака — это нормально):
```
curl https://rclone.org/install.sh | sudo bash
```
   Так работает на любом маке. `brew install rclone` тоже годится, но только
   если Homebrew уже стоит — иначе получишь «zsh: command not found: brew»,
   и ставить его ради одной программы незачем.
   Windows и Linux — установщик со страницы rclone.org/downloads.
2. Там же запусти вход и разреши доступ в открывшемся браузере:
```
rclone authorize "drive"
```
3. В терминале появится длинная строка вида `{"access_token":...}` — скопируй её целиком.
4. Теперь НА СЕРВЕРЕ отдай эту строку rclone, в одинарных кавычках:
```
sudo -u agent rclone config create gdrive drive token '<строка целиком>'
```
5. Проверь, что связь есть:
```
sudo -u agent rclone lsd gdrive:
```

**Что ты должен увидеть:** список папок твоего Google Drive. С этого момента
ночной бэкап сам кладёт архив в облако, в папку `dashi-<имя-агента>-backups`.

> Пункты 4–5 проще поручить самому агенту в Telegram: пришли ему строку из
> пункта 3 и попроси «заведи remote gdrive с этим токеном и прогони бэкап».
> Эта строка — ключ к твоему диску: как настроит, удали то сообщение из чата.

> ⚠️ Пароль от бэкапа (жёлтая строка на шаге 2) храни ОТДЕЛЬНО от сервера.
> Архивы в облаке зашифрованы им: нет пароля — нет и бэкапа.

# Команды агента в Telegram

Пиши их боту как обычные сообщения. Все команды видны и по `/help`.

| Команда | Что делает | Когда нужна |
|---|---|---|
| `/help` | список команд | забыл, что есть |
| `/status` | как агент себя чувствует: жив ли, сколько занято контекста, какая модель | «он завис или думает?» |
| `/stop` | прервать текущую работу | ушёл не туда, надо остановить |
| `/compact` | сжать разговор: суть остаётся, лишнее уходит | разговор длинный, а тему надо продолжить |
| `/new` | начать разговор с чистого листа | тема закрыта, переходим к другой |
| `/mirror on\|off` | показать в Telegram живое зеркало терминала | хочется видеть, что он там делает |
| `/keys` | панель кнопок: тап = нажатие в сессии | Claude Code спросил что-то своим диалогом |
| `/cc` | команды самого Claude Code, например `/cc model opus` | сменить модель и прочие настройки |
| `/relogin` | обновить вход в Claude: бот пришлёт ссылку, код кидаешь обычным сообщением | только у агентов БЕЗ годового токена, когда вход протух (раздел ниже); с годовым токеном не нужна |
| `/restart` | перезапустить мост целиком через systemd | бот тупит или подвисает, но команды ещё слышит |
| `/update` | обновить агента: бэкап → новый код → раскладка комплекта дисциплины (правила, стопоры, помощники, утренние кроны — по твоему поясу) → перезапуск, при сбое откат. Штатный способ догнать уже поднятого агента до свежих доработок. Не трогает только то, что живёт под root (юнит, `dashi-ctl`, хуки плагина, канарейку) — это повторный прогон установщика (шаг 4) | советник написал «вышло обновление», или ты сам знаешь, что пора; `/update force` — если правил код плагина руками |

`/relogin`, `/restart` и `/update` обрабатывает сам мост, а не Claude — поэтому они
работают даже с протухшим логином, когда агент на всё остальное молчит.

### Семантическая память (опция)

Кроме файлов (`memory/MEMORY.md` + заметки, поиск по словам) агент помнит **по
смыслу**: OpenViking — docker-контейнер на той же машине (~400 МБ RAM, порт 1933
только на localhost). Агент сам вспоминает релевантное на каждое сообщение и сам
запоминает важное. Кто считает «смысл»:

- **с ключом OpenAI** (`--openai-key KEY`, советую) — считает OpenAI, центы в месяц,
  оперативку сервера не ест. Замер 26.09.2026 на 200 живых записях: нужное находится
  первым в 17 случаях из 19;
- **без ключа** — маленькая локальная модель, ~0,7 ГБ оперативки, находит первым
  10 из 19. Если свободной памяти на сервере мало (меньше ~1,1 ГБ с учётом подкачки),
  установщик её пропустит — тогда остаётся только поиск по словам, а ключ это решает.

Ключ лежит только в `~agent/.openviking/ov.conf` (600). Перейти на ключ или сменить
его — повторный прогон установщика с `--openai-key`: накопленная память не теряется,
установщик сам пересчитает её под новую модель. Выключить — `docker rm -f openviking`
и `claude plugin uninstall claude-code-memory-plugin@openviking-plugin` под агентом.

Важное про `/stop`: он посылает в сессию Escape. Обычно останавливает, но
посреди тяжёлой операции может не успеть — это нормально, повтори.

# Контекст: что это и почему агент вдруг тупеет

**Простыми словами.** У агента есть «оперативная память разговора» — всё, что вы
уже написали друг другу за эту сессию. Она конечна. Чем длиннее разговор, тем
меньше свободного места, и тем хуже он держит детали: начинает переспрашивать,
терять договорённости, отвечать мимо.

Со стороны это выглядит как «поглупел». На деле — просто кончается место.

**Что делать.** Два лечения, разница простая:

- `/compact` — **сжать**. Он ужимает переписку до сути и продолжает ту же тему.
  Бери, когда работа не закончена.
- `/new` — **начать заново**. Полностью чистый лист, тема забывается (то, что он
  сохранил в память файлами, остаётся). Бери, когда переходишь к другому делу.

**Он предупредит сам.** В установщик вшит сторож: когда занято около 70%, агент
одной строкой скажет, что место заканчивается и пора `/compact`; около 85% —
скажет прямо в начале ответа, что дальше начнёт терять детали. Повторять каждый
ход он не будет — предупреждение приходит один раз на каждый порог.

Хочешь посмотреть цифру сам — `/status`, там строка с процентом заполнения.

**Правило на каждый день:** новая тема — `/new`. Это самая дешёвая привычка:
и отвечает точнее, и подписка тратится медленнее.

# Раз в ~30 дней: вход протухает (агент вдруг замолчал)

> **Это НЕ про тебя, если агент поставлен по этому гайду** — установщик с
> 25.08.2026 сразу берёт **годовой токен** (шаг 3, `claude setup-token` или
> флаг `--claude-token`), и вход не протухает. Раздел нужен только агентам со
> старым входом по ссылке (ставились раньше или руками). Проверить: в
> `/etc/dashi-plugin/<имя>/channel.env` есть строка `CLAUDE_CODE_OAUTH_TOKEN=`
> — значит, годовой токен есть. Нет строки — проще всего перевести агента на
> токен: повторный прогон установщика проведёт вход и запишет его.

Обычный вход в Claude по ссылке живёт около 30 дней, потом агент молча перестаёт
отвечать. Это не поломка, это ритуал. И с v6 он делается прямо из чата.

**Он сам скажет, когда пора.** Сторож на сервере видит экран «Login expired»
и пишет тебе в Telegram: «Вход в Claude протух — отправь /relogin»
(не чаще раза в 6 часов, спамить не будет).

**Основной путь — `/relogin` из чата, терминал не нужен:**

1. Отправь боту `/relogin`. Мост сам наберёт `/login` в сессии и пришлёт
   тебе кликабельную ссылку.
2. Открой ссылку и войди **В ТОТ ЖЕ аккаунт Anthropic, что и раньше**
   (сменишь аккаунт — уедут модель и лимиты). Появится код — скопируй.
3. Пришли код **обычным сообщением в тот же чат**. Мост сам вставит его в
   сессию и подтвердит, что вход обновлён.

На код даётся 15 минут; не успел — просто отправь `/relogin` ещё раз.
Работает это потому, что `/relogin` обрабатывает сам мост, а не Claude —
протухший логин ему не мешает.

**Запасной путь — через терминал.** Нужен, только если лежит и сам мост:
бот не реагирует даже на `/relogin`. Тогда по-старому, под root:

1. `su - agent`, затем `tmux capture-pane -pt channel-<имя> | tail -30` —
   убедись, что на экране «Login expired · Please run /login».
2. `tmux attach -t channel-<имя>` — ты внутри сессии агента.
   Набери `/login`, Enter — появится длинная ссылка.
3. Ссылка из терминала обычно НЕ копируется целиком. Рабочий способ — QR-код:
   выйди из tmux (Ctrl+B, отпустить, потом D) и выполни:

   ```
   tmux capture-pane -pJt channel-<имя> -S -100 | grep -o "https://[^ ]*" | tail -1 | qrencode -t ANSIUTF8
   ```

   (если `qrencode` не найден — разово под root: `apt install -y qrencode`).
   Отсканируй QR телефоном — ссылка откроется в браузере телефона.
4. Войди в тот же аккаунт, скопируй код.
5. `tmux attach -t channel-<имя>` → вставь код → Enter → «Login successful» →
   Enter → выйди (Ctrl+B, D).
6. Напиши боту — должен ответить.

Пока код не вставлен, экран `/login` не закрывай — ссылка одноразовая.

# Чтобы агент всё делал сам, а не гонял тебя под root

Четыре правила. Каждое — из реальной поломки, когда агент «вдруг разучился»
делать то, что делал вчера.

**1. Никогда не поднимай агента руками под root — и не заходи `su agent` без
дефиса.** Правильный перезапуск всегда один:

```
systemctl restart dashi-<имя>
```

Ручной tmux — только если сервиса нет совсем. И тогда строго после
`su - agent` **с дефисом**: без дефиса шелл остаётся с root-овским окружением,
агент не находит bun, и мост в Telegram мёртв при живом Claude (на экране
«bun: not found»). Проверка, что ты зашёл правильно: приглашение показывает
`~`, а не `/root`.

**2. Всё, с чем агент работает — отдай ему во владение.** Запустили что-то под
root в его папках — файлы перекрасились в root, и агент честно говорит «не могу
записать». Свежий установщик страхует дважды: каждый его прогон возвращает
юзеру владение ВСЕЙ домашней папкой, а у самого агента есть команда
самолечения — `sudo dashi-ctl-<имя> fix-owner`. Так что «файл принадлежит
root» агент теперь чинит сам, без тебя. Правило на будущее осталось: новый
проект для агента вне его домашней папки → сразу `chown -R agent:agent`.

**3. Самообслуживание — через ОДИН root-owned скрипт, а не набор sudoers-строк.**
Свежий установщик (от 21.08.2026) кладёт `/usr/local/bin/dashi-ctl-<имя>` —
принадлежит root, агенту разрешён через sudo одной строкой в
`/etc/sudoers.d/dashi-<имя>`. Умеет ровно восемь вещей:

```
sudo dashi-ctl-<имя> restart        # перезапустить свой сервис
sudo dashi-ctl-<имя> status         # состояние сервиса
sudo dashi-ctl-<имя> logs 200       # последние строки журнала
sudo dashi-ctl-<имя> fix-owner      # вернуть себе владение своими файлами
sudo dashi-ctl-<имя> vacuum         # ужать журнал systemd, если кончился диск
sudo dashi-ctl-<имя> update-claude  # обновить Claude Code
sudo dashi-ctl-<имя> check          # что нового в плагине (список коммитов; пусто = свежий)
sudo dashi-ctl-<имя> update         # обновить код моста и комплект дисциплины: бэкап, откат при сбое; `update force` — если правил код руками
```

`check` и `update` — то же, что делает `/update` из чата: обновляют код моста и
заново раскладывают комплект дисциплины (с поясом хозяина из `channel.env`).
Юнит, `dashi-ctl`, хуки плагина и канарейку они не трогают — для этого
повторный прогон установщика (шаг 4).

Почему так, а не отдельные права на systemctl/journalctl/chown: wildcard-права
в sudoers эскалируются до root — `journalctl` с любыми аргументами читает
произвольные файлы через `--file=`, а `chown` по глобу уводится через
симлинки. В root-owned скрипте пути зашиты намертво, аргументы проверяются
внутри, а переписать его агент не может. Полный sudo агенту не давать никогда.
Читать журнал своего сервиса агент может и вовсе без sudo — установщик
добавляет юзера в группу `systemd-journal`.

**4. Агент должен ЗНАТЬ свои права.** Установщик вписывает в шаблон CLAUDE.md
секцию «Самообслуживание»: какой у него сервис, что умеет dashi-ctl, что
channel.env он правит сам. Без неё права лежат мёртвым грузом, а агент
по-прежнему гоняет тебя в терминал. У уже установленных агентов CLAUDE.md
не перезаписывается — попроси агента самого дописать себе такую секцию
(образец — в шаблоне внутри `scripts/install-agent.sh`, секция
«Самообслуживание»).

Заодно про конфиг канала: `channel.env` теперь `660 root:юзер` — новый ключ
(Groq, chat_id и т.п.) агент вписывает сам и сам перезапускается, в терминал
ходить не надо.

- **[СЕРВЕР]** — команда внутри сервера (после SSH).

## Три решения, которые экономят день (прочти до старта)

Мы набили эти шишки — ты не набивай:

1. **Агент живёт под ОТДЕЛЬНЫМ не-root пользователем, а НЕ под root.**
   Полная автономия («агент сам всё делает, ничего не подтверждаешь») под root
   технически НЕВОЗМОЖНА — Claude Code отказывается работать в режиме без
   подтверждений от имени root. Поэтому мы сразу создаём юзера `agent` и всё
   ставим под ним. Если поставить под root, а потом захотеть автономию —
   придётся переносить всё заново (мы так и потеряли время).

2. **Длинный код НЕ копируется через Telegram надёжно.** Копипаст кода из чата в
   редактор на сервере глючит (особенно на Mac). Поэтому файлы со скриптами
   пусть пишет САМ агент прямо на диск сервера — не через чат.

3. **Вход в Claude делаем прямо на сервере** (способ с браузером). Копирование
   логина с Mac и вход через приложение — НЕ работают для CLI.

Зачем: см. «решение №1» выше — под root не будет полной автономии.


# ЧАСТЬ D. Голос (расшифровка голосовых)

Зачем: без ключа Groq текст работает, а голос — нет.

1. **[БРАУЗЕР]** console.groq.com → залогинься → «Create API Key» → скопируй
   (начинается на `gsk_`). Бесплатно, лимитов на голос с запасом хватает.
2. Впиши ключ в `channel.env` (строка `GROQ_API_KEY=...`, Шаг 10) и перезапусти
   сервис (`systemctl restart ...` из Части F).

# ЧАСТЬ E. Автозапуск 24/7 (systemd)

Зачем: агент стартует сам при перезагрузке и поднимается после сбоя. Claude
Code — интерактивная программа, ей нужен «экран», поэтому держим её в tmux.

Проще всего НЕ писать юнит руками, а прогнать установщик (шаг 2 быстрого пути,
`--user agent`) — он ставит уже отлаженную схему. Живой день отладки 20.08.2026
показал, что наивный юнит ломается сразу тремя способами:

> ⚠️ ГРАБЛЯ: `Type=forking` + tmux — мина. systemd теряет главный процесс
> демонизировавшегося tmux и через секунду сам гасит только что поднятого
> агента. Рабочая схема: `Type=simple` + скрипт-держатель, который поднимает
> сессию и живёт, пока жива она.
> ⚠️ ГРАБЛЯ: слепые `send-keys Enter` по таймеру жмут не те кнопки: набор
> стартовых вопросов от запуска к запуску РАЗНЫЙ (принятые запоминаются), и
> «вниз+Enter» попадал в диалог dev-каналов, выбирая «Exit» — сервис сам убивал
> Claude. Жать надо глядя на экран (`tmux capture-pane` → нужная клавиша).
> ⚠️ ГРАБЛЯ: запуск голого `claude` в юните умирает на окружении — запускать
> через `/bin/bash -lc '...'`, чтобы подтянулся PATH юзера (bun и прочее).

Если всё же руками — установщик кладёт два скрипта, повтори их логику:
`/usr/local/bin/dashi-run <сессия> <папка-plugin>` (kill-session → new-session
с `bash -lc 'cd ... && exec claude ...'` → проверка, что tmux-сессия реально
поднялась → фоновый прожиматель диалогов → цикл раз в 15 сек, пока жива
сессия) и `/usr/local/bin/dashi-press-dialogs` (смотрит экран до 2 минут —
слабый VPS грузит Claude дольше 45 сек: «Bypass Permissions» → Down+Enter,
остальные диалоги → Enter).

В цикле dashi-run сидит ещё и сторож моста: он щупает вебхук-порт
(127.0.0.1 и порт из `TELEGRAM_WEBHOOK_PORT` в `channel.env`, по умолчанию
8089; у второго агента на сервере — свой). Порт был жив и пропал на 2 проверки подряд → dashi-run
выходит ненулевым, systemd перезапускает всё целиком. Это закрывает классику
«tmux жив, мост сдох»: systemd доволен, бот молчит, чинить только терминалом.
До первого подъёма порта сторож не проверяет — на свежей установке Claude
может сколько угодно стоять на экране логина.

И мелочь, которая спасает диск: установщик кладёт drop-in
`/etc/systemd/journald.conf.d/dashi.conf` с `SystemMaxUse=500M` — без потолка
журнал systemd за месяцы съедает гигабайты на маленьком VPS.
Юнит: `Type=simple`, `ExecStart=/usr/local/bin/dashi-run ...`,
`ExecStop=tmux kill-session`, `Restart=always`, `RestartSec=15s`, плюс
`EnvironmentFile` с токенами и `Environment=HOME=...`. Точный текст — в
`scripts/install-agent.sh` репозитория, секция «8. systemd».

Проверь автозапуск после перезагрузки: `systemctl is-enabled dashi-<имя>` → `enabled`.

Приём для богатого характера: скорми боту файл-интервью — попроси задать по
порядку вопросы (чем занимаешься, как обращаться, стиль, часовой пояс, запреты) и
записать ответы в CLAUDE.md. Тогда характер соберётся сам, без ручной писанины.

# ЧАСТЬ F. Память агента (помнит между сессиями)

Зачем: чтобы агент помнил тебя, проект и твои правки, а не начинал с нуля.

Самый простой рабочий вариант — файловая память. Скорми боту **одним
сообщением** ТЗ:

**[БОТУ]**:
```
Организуй себе долгую память. Создай в моём workspace (рядом с CLAUDE.md):
- папку memory/ и в ней файл MEMORY.md — индекс, одна строка на факт
  «- [Заголовок](файл.md) — короткий хук»;
- каждый факт — свой файл memory/имя.md с шапкой (name, description,
  type: user/project/feedback/reference) и телом-фактом.
В CLAUDE.md впиши правила: при старте читаю MEMORY.md; узнал факт или получил
правку — сохраняю новый файл + строку в индекс; память против реальности —
реальность выше.
Заполни сразу файл обо мне: кто я, чем занимаюсь, как обращаться, часовой пояс.
```
Дальше просто говоришь «запомни, что…» — копит сам.

Хочешь многослойку (как у продвинутых агентов): добавь папку `core/` с файлами
`USER.md`, `rules.md` (правила и правки), `decisions.md` (решения ~14 дней),
`handoff.md` (последние 5 итогов), `LEARNINGS.md` (уроки), а в CLAUDE.md через
`@include` подключи ТОЛЬКО лёгкие `USER.md` и `rules.md` — остальное агент читает
по требованию, чтоб не жечь контекст. Тоже отдаётся боту одним ТЗ.

# ЧАСТЬ G. Бот-ремонтник — ставит установщик

Раньше здесь была инструкция «попроси агента написать Python-скрипт и перенеси
его в /root». Она устарела: ремонтника ставит установщик (шаг 8 быстрого
пути) — вопросом про токен в конце прогона или флагом `--repair-token`.

Что он кладёт: отдельный процесс `claude-code-telegram` в `/opt/repair-<имя>/`
(свой venv, свой `.env` с токеном второго бота), юнит
`claude-repair-<имя>.service` от того же пользователя `agent`, права — те же,
что у агента (sudo только на `dashi-ctl-<имя>`). Работает на том же годовом
токене Claude, отдельного входа не нужно. Живёт вне tmux-моста, поэтому
переживает смерть агента.

Проверка: `systemctl status claude-repair-<имя>` → active, второй бот
отвечает на «привет». Не стартовал — `journalctl -u claude-repair-<имя> -n 30`.

**Как чинить, если «перезапусти агента» через ремонтника не помогает:**
1. Попроси ремонтника показать логи (`journalctl -u dashi-<имя> -n 50`) —
   частое: перегруз сервера / кончилась память, битый конфиг.
2. По SSH под root: `systemctl status dashi-<имя>`, потом
   `su - agent -c 'tmux attach -t channel-<имя>'` — реальная ошибка часто в
   самом окне Claude. Выход из tmux: Ctrl+B, потом D.
3. Глухо висит весь сервер — `reboot` целиком (оба сервиса в автозапуске,
   встанут сами).

# Карта файлов

Так раскладывает установщик (`~` = домашняя папка пользователя `agent`,
`<имя>` = имя агента):

```
~/.claude/settings.json                                  — сюда встают hooks (плагина и комплекта)
~/.claude.json                                           — отметка о пройденном первом запуске Claude
~/.claude-lab/<имя>/.claude/CLAUDE.md                    — характер агента
~/.claude-lab/<имя>/.claude/core/                        — конституция, правила, профиль хозяина, леджер
~/.claude-lab/<имя>/.claude/memory/                      — память агента
~/.claude-lab/<имя>/.claude/hooks/ + agents/             — гейт-хуки и помощники из комплекта
~/.claude-lab/<имя>/.claude/dashi-plugin-claude-code     — плагин (ВНУТРИ workspace!)
~/.claude-lab/<имя>/bin/                                 — скрипты комплекта (сводка, будильник, bg.sh)
~/.claude-lab/<имя>/secrets/                             — ключи, которые агент хранит сам (700; пароль бэкапа тут же)
~/.claude-lab/<имя>/backups/                             — шифрованные бэкапы
~/.claude-lab/<имя>/.kit-backup/<дата>/                  — старые версии файлов комплекта, которые повторный прогон перезаписал
~/.claude-lab/<имя>/state/telegram/                      — состояние моста, config.json карточки прогресса
/etc/dashi-plugin/<имя>/channel.env                      — токен бота, id, ключи, годовой токен Claude (660 root:agent)
/etc/systemd/system/dashi-<имя>.service                  — автозапуск основного
/etc/systemd/system/claude-repair-<имя>.service + /opt/repair-<имя>/ — бот-ремонтник (его .env — там же)
/usr/local/bin/dashi-run + dashi-press-dialogs           — держатель сессии + прожиматель диалогов
/usr/local/bin/dashi-ctl-<имя> + /etc/sudoers.d/dashi-<имя> — самообслуживание агента (root-owned)
/etc/cron.d/dashi-<имя>-{advisor,modal,backup}           — советник, прожиматель модалок, бэкап
crontab пользователя agent                               — утренняя сводка и будильник по срокам
```

Ручной путь (ниже) кладёт `channel.env` иначе — в
`~/.claude-lab/<имя>/secrets/channel.env` (600), — и юнит называет по-своему.

# Железное правило безопасности

Любую починку/переустановку МОСТА делай из **терминала сервера, НЕ из Telegram**.
Ты меняешь тот самый канал, которым шлёшь команды — сломается на середине,
Telegram замолчит, и чинить будет нечем. Порядок: терминал на сервере → правка →
доктор → тестовое сообщение → только потом ушёл. (Именно для аварий из терминала
и существует бот-ремонтник — он единственное исключение, потому что он отдельный
процесс.)

# Быстрый траблшутинг (симптом → причина → фикс)

| Симптом | Причина | Фикс |
|---|---|---|
| Бот молчит после запуска | Запустил не из папки `plugin` | `cd .../plugin`, запускай оттуда |
| «no MCP server configured» | То же — неверная папка | Запуск из `plugin` |
| Claude падает сразу, tmux пуст | Режим без подтверждений под root | Перенести на не-root юзера (Часть C) |
| Спрашивает подтверждения на всё | Нет `--dangerously-skip-permissions` / под root | Не-root юзер + флаг в юните |
| Вход в Claude не проходит | Пытаешься через claude.ai/приложение | OAuth прямо на сервере (Шаг 5) |
| Голос не расшифровывается | Нет `GROQ_API_KEY` | Впиши ключ, перезапусти сервис |
| Код из чата вставляется криво | Копипаст длинного кода в терминал | Пусть агент пишет файлы на диск |
| Сессия зависла на старте (на экране стартовый вопрос Claude) | Стартовые диалоги не прожаты | У установщика это делает `dashi-press-dialogs` (запускается из `dashi-run`, смотрит на экран до 2 минут и жмёт нужное) — просто `systemctl restart dashi-<имя>`. Руками: `tmux send-keys -t channel-<имя> Enter` (без attach), на «Bypass Permissions» — `Down`, потом `Enter` |
| Claude живой, бот молчит, на экране «bun: not found» | Сессию подняли руками из `su agent` БЕЗ дефиса или под root | `systemctl restart dashi-<имя>`; руками — только после `su - agent` |
| Молчит, сторож написал «вход в Claude протух» | Месячный перелогин | Отправь боту `/relogin`; мост тоже лежит — раздел «Раз в ~30 дней» выше |
| Агент: «файл принадлежит root, записать не могу» | Что-то запускали/правили под root в его папках | Попроси агента: `sudo dashi-ctl-<имя> fix-owner`; папки вне его дома — под root `chown -R agent:agent <папка>` |
| Агент просит выполнять команды под root | Нет dashi-ctl / секции «Самообслуживание» в CLAUDE.md | Раздел «Чтобы агент всё делал сам» выше |
| Бот тупит, но команды слышит | Мост подзавис | `/restart` боту, подожди минуту |
| Claude живой, а в Telegram молчит (в терминале агента всё отвечает) | Свежий Claude Code не читает описание моста из папки плагина | Прогони установщик ещё раз (он регистрирует мост на уровне пользователя) или руками: `su - agent -c 'cd .../plugin && claude mcp add -s user dashi-channel -- bun ./src/server.ts'` при ОСТАНОВЛЕННОЙ службе, затем `systemctl start dashi-<имя>` |
| Служба перезапускается по кругу, на экране вопрос про доверие к папке | Новый диалог Claude «Do you trust the files in this folder?» с выбором «No, exit» по умолчанию | Обнови установщик и прогони повторно; руками — в tmux выбрать «Yes, proceed» |
| Основной завис, не отвечает | Разное | Ремонтнику `/restart`, не помог — `reboot` |
