# Как поднять агента из бэкапа — по шагам

Инструкция для человека, а не для программиста. Делай строго сверху вниз, ничего
не пропускай. Где надо что-то вставить — вставляешь целиком блок и жмёшь **Enter**.

**Держи под рукой (это должно лежать НЕ на сервере — в заметках/менеджере паролей):**
- Пароль от бэкапа (показывался один раз при установке).
- Доступ к Google Drive, где лежит бэкап (папка `dashi-<имя-агента>-backups`).
- Доступ к GitHub (аккаунт `popovalex17071985-source`).
- Root-пароль от сервера (в панели хостинга).

Дальше `<агент>` = имя твоего агента (например `lena`). Подставляй везде своё.

---

# Случай 1. Бот молчит, но сервер жив (забанили Claude)

Самый лёгкий. Сервер и данные целы — просто заново войти в Claude.

**Шаг 1.** Зайди на сервер. На Mac открой программу «Терминал», впиши (свой IP
вместо `АЙПИ`) и нажми Enter, потом введи root-пароль:
```
ssh root@АЙПИ
```
> На Mac перед этим **выключи VPN** — иначе не пустит.

**Шаг 2.** Получи новый годовой токен. Впиши:
```
su - agent -c 'claude setup-token'
```
Появится длинная ссылка — открой её в браузере на телефоне/компе, войди в
**тот же** аккаунт Claude, что был раньше, скопируй код со страницы, вернись в
терминал, вставь код, Enter. В конце на экране напечатается токен — длинная
строка, начинается с `sk-ant-oat01-`. Скопируй её целиком.

**Шаг 3.** Отдай токен установщику (замени `ТОКЕН` на скопированную строку):
```
sudo bash dashi-plugin-claude-code/scripts/install-agent.sh --name <агент> --claude-token ТОКЕН
```
Он запишет токен куда надо и сам перезапустит агента.

**Шаг 4.** Напиши боту в Telegram. Ответил — всё, готово.

# Случай 2. Сервер умер (нужен новый с нуля)

**Шаг 1. Купи новый сервер.** У любого хостинга закажи VPS с **Ubuntu 22.04**.
После оплаты тебе дадут **IP-адрес** и **root-пароль** (на почту или в панели).

**Шаг 2. Зайди на сервер.** На Mac открой «Терминал», впиши (свой IP вместо
`АЙПИ`), Enter, введи root-пароль:
```
ssh root@АЙПИ
```
> VPN на Mac выключи.

**Шаг 3. Скачай код агента.** Скопируй строку целиком, вставь, Enter:
```
git clone https://github.com/popovalex17071985-source/JohnRamboAgent.git
```

**Шаг 4. Возьми бэкап.** Открой Google Drive в браузере, зайди в папку
`dashi-<агент>-backups`, скачай **самый свежий** файл (имя вида
`<агент>-20260824-0340.tar.gz.gpg`). Затем закинь его на сервер — проще всего
так, с СВОЕГО компа (не с сервера), в новом окне терминала:
```
scp ~/Downloads/<агент>-20260824-0340.tar.gz.gpg root@АЙПИ:/root/
```
> Тут `~/Downloads/...` — куда браузер скачал файл; `АЙПИ` — адрес сервера.
> Если запутался на этом шаге — зови меня или айтишника, остальное дальше простое.

**Шаг 5. Одна команда восстановления.** Вернись в окно, где ты на сервере
(`root@...`). Вставь целиком, Enter:
```
sudo bash dashi-plugin-claude-code/scripts/restore-agent.sh \
     --name <агент> \
     --archive /root/<агент>-20260824-0340.tar.gz.gpg
```
Она сама всё поставит и разложит. **Спросит пароль от бэкапа** — впиши тот самый
пароль из заметок, Enter. (Пароль не отображается при вводе — это нормально.)

**Шаг 6. Дождись «агент <агент> восстановлен».** Это займёт несколько минут
(ставит программы). Память, секреты, токен бота, расписание, сам сервис — уже на
месте.

**Шаг 7. Напиши боту в Telegram.** Вход в Claude обычно НЕ нужен — годовой
токен приезжает из бэкапа вместе с настройками. Ответил — агент воскрес.

Молчит дольше пары минут — значит токен успел протухнуть (ему год): сделай
Случай 1, шаги 2–3, и напиши боту снова.

---

## Если что-то пошло не так

- «пароль неверный» на шаге 5 → перепроверь пароль от бэкапа (без лишних пробелов).
- Файл на сервер не закидывается (шаг 4) → это единственное реально муторное
  место, зови айтишника или меня с другого сервера — покажу.
- Всё остальное делает одна команда; если она дошла до «восстановлен» — данные целы.

## Полезное про сам бэкап (можно не читать)

Бэкап делается сам раз в сутки (`scripts/agent-backup.sh`, крон в 03:40): один
зашифрованный файл со всем, чего нет на GitHub — память, характер, секреты,
состояние, токен бота, расписание. Хранится 7 последних копий; если подключено
облако — копия уезжает туда (**только облачная копия переживёт смерть сервера**).
Каждая свежая копия сразу проверяется на расшифровку — битую бэкап удаляет сам.

Проверить, что восстановление вообще рабочее, не дожидаясь ЧП (ничего живого не
трогает):
```
bash tests/restore-agent-e2e.sh
```

_Главное: держи ВНЕ сервера пароль от бэкапа и доступ к GitHub/Google Drive. Без
них не восстановит никто, с ними — восстановит любой._

## Google Drive: свой ключ обязателен (иначе «квота превышена»)

**Симптом:** `rclone` начинает падать с ошибкой квоты — листинг папки то проходит,
то нет, скачивание файла не проходит вовсе. Диск при этом свободен.

**Причина:** по умолчанию rclone ходит в Google под СВОИМ общим ключом, одним на
всех пользователей rclone в мире. В часы пик этот общий лимит выбирается чужими
людьми, и твой бэкап просто не доезжает. Паузы между запросами (`pacer-min-sleep`)
лечат симптом частично и не лечат причину.

**Лечится один раз, за 5 минут, бесплатно** — заводится собственный ключ. Биллинг
и карта не нужны.

1. Открой https://console.cloud.google.com/ под тем же Google-аккаунтом, где лежит
   Drive агента. Создай проект (любое имя, например `dashi-backups`).
2. «APIs & Services» → «Library» → найди **Google Drive API** → **Enable**.
3. «APIs & Services» → «OAuth consent screen» → тип **External** → заполни только
   обязательные поля → в разделе «Test users» добавь свой же Google-адрес.
4. «APIs & Services» → «Credentials» → «Create credentials» → **OAuth client ID** →
   тип **Desktop app**. Скопируй выданные `Client ID` и `Client secret`.
5. На сервере агента: `rclone config` → `e` (edit remote) → выбери `gdrive` →
   вставь свой `client_id` и `client_secret` → дальше по умолчанию, авторизацию
   подтверди в браузере.
6. Проверь: `rclone about gdrive:` — должен отдать размеры, а не ошибку.

Проверить, есть ли свой ключ уже сейчас:

```bash
grep -c client_id ~/.config/rclone/rclone.conf   # 0 = сидишь на общем, надо заводить
```

Пока своего ключа нет — бэкап работает «как повезёт»: в тихие часы проходит, в пик
падает. Это не поломка агента и не поломка сервера.
